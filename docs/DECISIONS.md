### D-001 — Выбор технологического стека и структуры репозиториев
- Дата: 2026-11-16
- Тип: решение
- Решение:
  1) Оба мобильных приложения (**uGym** и **uGym Business**) разрабатываются на **Flutter 3.x (Dart)** как отдельные проекты и отдельные git-репозитории.
  2) Общее сетевое ядро, форматтеры, маппер ошибок и реализация дизайн-системы **uCraft Design System 1.0 (Midnight & Cobalt)** выносятся в общий пакет `ugym_core`.
  3) Архитектура кода внутри приложения: `Feature-First` Clean Architecture (`domain` / `data` / `presentation`).
- Причина: единая кодовая база для iOS и Android (включая планшетный режим киоска и навигационный rail), строгая типизация Dart и единая дизайн-система uCraft.
- Затронутые разделы ТЗ: `uGym_Business_Mobile_TZ.md` (раздел 2), `uCraft_Design_System.md` (раздел 21)
- Статус: принято


### D-002 — Подключение ugym_core и хранение лёгких настроек приложения
- Дата: 2026-11-16
- Тип: решение
- Решение:
  1) Общий пакет `ugym_core` подключается в `pubspec.yaml` по локальному пути `path: ../ugym_core` на этапе параллельной разработки (с возможностью переключения на git-зависимость перед релизным CI).
  2) Лёгкие пользовательские настройки (`theme_mode`, `locale_code`, `selected_gym_id`, `selected_gym_timezone`) сохраняются через `AppPreferences` поверх `TokenStorage` из `ugym_core` без добавления отдельного плагина `shared_preferences`.
- Причина: единое защищённое хранилище для токена, PIN киоска и настроек темы/филиала без лишних нативных зависимостей (KISS/YAGNI).
- Затронутые разделы ТЗ: `uGym_Business_Mobile_TZ.md` (раздел 2.2), `uCraft_Design_System.md` (раздел 22), `B0-02`
- Статус: принято
