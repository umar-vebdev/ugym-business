### D-001 — Выбор технологического стека и структуры репозиториев
- Дата: 2026-11-16
- Тип: решение
- Решение:
  1) Оба мобильных приложения (**uGym** и **uGym Business**) разрабатываются на **Flutter 3.x (Dart)** как отдельные проекты и отдельные git-репозитории.
  2) Общее сетевое ядро, форматтеры, маппер ошибок и реализация дизайн-системы **uCraft Design System 1.0 (Midnight & Cobalt)** выносятся в общий пакет `ugym_core`.
  3) Архитектура кода внутри приложения: `Feature-First` Clean Architecture (`domain` / `data` / `presentation`).
- Причина: единая кодовая база для iOS и Android (включая планшетный режим киоска и навигационный rail), строгая типизация Dart и единая дизайн-система uCraft.
- Затронутые разделы ТЗ: `uGym_Business_Mobile_TZ.md` (раздел 2), `uCraft_Design_System.md` (раздел 21)
- Статус: принято


### D-002 — Подключение ugym_core и хранение лёгких настроек приложения
- Дата: 2026-11-16
- Тип: решение
- Решение:
  1) Общий пакет `ugym_core` подключается в `pubspec.yaml` по локальному пути `path: ../ugym_core` на этапе параллельной разработки (с возможностью переключения на git-зависимость перед релизным CI).
  2) Лёгкие пользовательские настройки (`theme_mode`, `locale_code`, `selected_gym_id`, `selected_gym_timezone`) сохраняются через `AppPreferences` поверх `TokenStorage` из `ugym_core` без добавления отдельного плагина `shared_preferences`.
- Причина: единое защищённое хранилище для токена, PIN киоска и настроек темы/филиала без лишних нативных зависимостей (KISS/YAGNI).
- Затронутые разделы ТЗ: `uGym_Business_Mobile_TZ.md` (раздел 2.2), `uCraft_Design_System.md` (раздел 22), `B0-02`
- Статус: принято


### D-003 — Зависимости киоск-режима QR (crypto, qr_flutter, wakelock_plus)
- Дата: 2026-11-17
- Тип: решение
- Решение: в `pubspec.yaml` добавлены пакеты:
  1) `crypto` — для вычисления SHA-256 хеша 4-значного PIN-кода выхода из киоска с солью устройства в `TokenStorage`;
  2) `qr_flutter` — для генерации стандартных сканируемых QR-матриц (ISO/IEC 18004) по динамическому HMAC-токену зала;
  3) `wakelock_plus` — для предотвращения выключения экрана планшета/смартфона в режиме стойки через абстракцию `KioskWakeLock`.
- Причина: прямое требование безопасности и UX киоска из раздела 2.4 и 5.2.1 `uGym_Business_Mobile_TZ.md`; обёртка `KioskWakeLock` сохраняет простоту widget-тестов без платформенных каналов.
- Затронутые разделы ТЗ: `uGym_Business_Mobile_TZ.md` (разделы 2.4, 5.2.1), `B1-05`
- Статус: принято

### D-005 — Автоопределение роли тренера при входе через `GET /business/schedule/sessions/1/bookings`
- Дата: 2026-11-19
- Тип: [ASSUMPTION]
- Решение: в `BusinessSessionController.bootstrapFromApi` после получения `403 FORBIDDEN` от `/business/staff` и `/business/gyms` выполняется проба `GET /business/schedule/sessions/1/bookings`. Ответ `200`, `404 NOT_FOUND` или `403 SUBSCRIPTION_EXPIRED` означает, что пользователь прошёл проверку принадлежности к штату компании и является тренером (`BusinessRole.trainer`); ответ `403 FORBIDDEN` означает, что пользователь не состоит в компании (`BusinessRole.noCompany`).
- Причина: в текущей OpenAPI-спецификации (`identity-auth.yaml`, `schedule.yaml`) `/api/v1/user` не возвращает роль в компании, а единственный эндпоинт `/business/*`, доступный тренеру — `GET /business/schedule/sessions/{session}/bookings`. Решение обратимо: при появлении отдельного поля роли в `/user` пробу можно заменить без изменения интерфейса.
- Затронутые разделы ТЗ: `uGym_Business_Mobile_TZ.md` (раздел 1), `docs/api/schedule.yaml`, `B5-01`
- Статус: принято


### D-006 — Выбор и нативное сжатие фотографий витрины (image_picker)
- Дата: 2026-11-19
- Тип: решение
- Решение: добавлен официальный плагин `image_picker` для выбора фотографий витрины зала из системного Photo Picker (Android/iOS) с нативным сжатием до `maxWidth: 1920`, `maxHeight: 1920`, `imageQuality: 85` через обёртку `pickGymPhotoFromGallery` (`GymPhotoPicker`), подменяемую в тестах.
- Причина: прямое требование раздела 5.7.3 и 6.3.2 `uGym_Business_Mobile_TZ.md` (загрузка до 10 фото в форматах `jpeg`/`png`/`webp` до 5 МБ со сжатием на устройстве через системный Photo Picker без дополнительных разрешений на хранилище).
- Затронутые разделы ТЗ: `uGym_Business_Mobile_TZ.md` (разделы 5.7.3, 6.3.2), `docs/api/gym-photos.yaml`, `B5-04`
- Статус: принято

### D-010 — Визуальная доработка Midnight — Soft

- Дата — 2026-11-20
- Тип — решение по макетам

### D-011 — Светлые компоненты на тёмном фоне uGym Business

- Дата — 2026-11-20
- Решение — в тёмной теме использовать фон Midnight Soft `#151C29`. Карточки, поля, кнопки, статусы и панели навигации используют одну светлую палитру в обеих темах. Для текста на тёмном фоне предусмотрены отдельные контрастные цвета.
- Реализация — палитра подключена через текущие токены uCraft. Светлые панели используют светлый режим компонентов, в том числе для кнопок удаления. Общий пакет `ugym_core` продолжает предоставлять базовые компоненты обоим приложениям.
- Причина — согласованный вариант «Мягкий тёмный фон, карточки и кнопки из светлой темы».

### D-012 — Векторный знак uCraft на экране входа

- Дата — 2026-11-20
- Решение — использовать светлый компактный знак `08-avatar-light.svg` из утверждённого бренд-кита. В приложении используется его векторная версия из `ea222a3`, где надпись переведена в контуры с сохранением цветов и пропорций.
